## 1. สิ่งที่ user เคาะแล้ว (ห้ามเปลี่ยนเองโดยไม่ถาม)

Avatar
- พิกเซลอาร์ต ตัวสูงราว 3 หัว ยืนหน้าตรงท่าเดียว ร่างเดียวไม่แยกเพศ
- ขอบเข้ม 1px + ขอบขาว 2px รอบตัวแบบโทเค่นบอร์ดเกม คำนวณอัตโนมัติจากรูปร่างรวม
- ตัวละครสูง 36px กว้างราว 14px วางบนกรอบ 40x44 (เผื่อปีก หมวกสูง วงแหวน ของในมือ)
- ซื้อครั้งเดียวเก็บถาวร ใส่ได้ช่องละ 1 ชิ้น (โมเดลเดียวกับ `data/cosmetics.js`)
- ในโค้ดใช้คำว่า `doll` เพราะ `utils/avatar.js` ถูกใช้กับรูปโปรไฟล์ไปแล้ว

PharMarble (ชื่อในโค้ด `marble`)
- ชื่อช่องเป็นจังหวัด สิ่งปลูกสร้างเป็นร้านยา 3 ระดับ แล้วต่อด้วยแลนด์มาร์ค
- เงินในเกมแยกจากเหรียญเว็บ เริ่มคนละ 2M (แบบห้องเอโคโนมี)
- สมบัติรอบแรก 10 ชิ้น ใส่ได้ 3 ช่อง อัปได้ 5 เลเวลด้วยเหรียญเว็บ · user สั่งว่าไม่ต้องจูนละเอียด
- ลูกเต๋าซื้อด้วยเหรียญเว็บ คุมแต้มได้ด้วยหลอดจังหวะ
- ทุกห้องใช้ของจริงของแต่ละคน ไม่มีห้องปรับเลเวลให้เท่ากัน (user: คนน้อย เกมไม่ซีเรียส ถือเป็นเรื่องดวง)
- รางวัลจบเกม: เหรียญน้อย + ชุด Avatar พิเศษตามจำนวนครั้งที่ชนะ
- ไม่ทำโหมดติว (ตอบข้อสอบในเกม)

ยังไม่เคาะ: **ราคาทุกอย่าง** (เสื้อผ้า ลูกเต๋า ค่าอัปสมบัติ) user จะเคาะทีหลัง ใส่ค่าตั้งต้นจากแผนไว้ในไฟล์ data แล้วทำให้แก้ที่เดียว

## 4. รูปแบบข้อมูลชิ้นส่วน

กริดเป็นตารางตัวอักษร ตัวอักษรหนึ่งตัวคือหนึ่งพิกเซลและชี้ไปที่สีในพาเลต `.` คือโปร่งใส
ชิ้นส่วนเป็นรายการแพตช์ `[แถว, คอลัมน์, "สตริง"]` วางทับตัวฐาน ชิ้นที่อยู่หลังตัว (ปีก) ใส่ไว้ใน `back` จะวาดเฉพาะพิกเซลที่ว่าง

ลำดับซ้อนจากหลังไปหน้า: back (ปีก, ผมหลัง) → ตัว+สีผิว → กางเกง/กระโปรง → รองเท้า → เสื้อ → เสื้อคลุม → ตา → ปาก → ผมหน้า → หมวก → แว่น/มาสก์ → ของในมือ

ช่อง (key ใช้ในรหัส `dl` และ `eq`): `s` สีผิว · `h` ทรงผม · `c` สีผม · `e` ตา · `m` ปาก · `t` เสื้อ · `b` กางเกง/กระโปรง · `k` รองเท้า · `o` เสื้อคลุม · `x` หมวก · `a` แว่น/มาสก์ · `i` ของในมือ · `w` ปีก/ของติดหลัง (ช่องแยก เคาะแล้ว ใส่พร้อมเสื้อคลุมได้)

เปลี่ยนสีด้วยการสลับพาเลต: ตัวอักษร `S s` ผิว/เงาผิว · `H L` ผม/ไฮไลต์ผม · `T t` เสื้อ/เงาเสื้อ · `P p` กางเกง/เงา · `B` รองเท้า · ที่เหลือเป็นสีตายตัวของชิ้น
หมวกที่ครอบหัวมีธง `hideHairTop` เพื่อไม่ให้ผมทะลุ

ท่อนบนกับท่อนล่างเป็นคนละช่อง (`t` กับ `b`) เคาะแล้ว · ชุดเต็มตัว (เดรส ครุย ชุดหมี จั๊มสูท) เป็นชิ้นในช่อง `t` ที่มีธง `full: true`:
- ใส่แล้วกินช่อง `b` อัตโนมัติ: ไม่วาดท่อนล่าง และแท็บท่อนล่างในตู้เสื้อผ้าขึ้นว่าถูกชุดนี้ใช้อยู่
- ไม่ลบค่า `eq.b` เดิม ถอดชุดเต็มตัวแล้วท่อนล่างเดิมกลับมาเอง
- เลือกท่อนล่างชิ้นใหม่ขณะใส่ชุดเต็มตัว = ถอดชุดเต็มตัวกลับเป็นเสื้อเริ่มต้น แล้วใส่ท่อนล่างนั้น
- ซื้อครั้งเดียวได้ทั้งชุด นับเป็น 1 ชิ้นในแคตตาล็อก
- ใช้หลักเดียวกันกับชิ้นอื่นที่กินหลายช่องผ่านฟิลด์ทั่วไป `covers: ['b']` (เช่น ชุดมาสคอต `covers: ['b','k','x']`) ให้ตัวเรนเดอร์ข้ามช่องที่ถูก cover

## 6. Data model ส่วน Avatar

- `src/data/dollParts.js` แคตตาล็อก `{ id, slot, tier, label, price, free?, ev?, pk? }` (รูปแบบเดียวกับ `COSMETICS` รวมธงอีเวนต์)
- `users/{uid}.doll = { owned: [], eq: { s,h,c,e,m,t,b,k,o,x,a,i } }` เพิ่มใน `USER_DEFAULTS` + `normalizeUserData`
- แถว roster เพิ่มฟิลด์ `dl` สตริงสั้นไม่เกิน 40 ตัวอักษร เช่น `s1h04c2e01m01t03b02k01` (ดูวิธีที่ n/f/b ของ cosmetics ขี่ไปกับ roster ใน `useRosterSync.js`)
- id สั้นและห้ามเปลี่ยนหลังปล่อย
- ชุดเริ่มต้นฟรี: สีผิวและสีผมทุกสี, ผม 3 ทรง, ตา 2, ปาก 2, เสื้อ 2 (รวมชุดนักศึกษา), กางเกง/กระโปรง 2, รองเท้า 1
- หน้าจอ: `views/DollView.vue` (ตู้เสื้อผ้า เข้าจากหน้าฉัน) ครึ่งบนตัวละคร ครึ่งล่างแท็บช่อง + ตารางชิ้น ลองใส่ได้ก่อนซื้อ ปุ่มซื้อรวดเดียวทั้งชุดที่ลองอยู่

## 7. สรุป PharMarble ที่ต้องรู้ก่อนทำส่วน B

- 2-4 คน คนละเครื่อง หัวห้องประมวลผล (แบบ `usePoker.js`) ไม่มีข้อมูลลับ จึงไม่ต้องมี path secrets/dealer
- engine เป็น pure function: `createGame(players, opts, seed)`, `apply(state, action)` คืน state + events · RNG จาก seed ใน state เพื่อให้หัวห้องคนใหม่รับช่วงได้
- กระดาน 32 ช่อง: เมือง 20 (8 กลุ่มสี), ท่องเที่ยว 4, การ์ดดวง 3, ภาษี 1, มุม 4 (จุดเริ่มต้น, เกาะร้าง, เทศกาล, เที่ยวรอบโลก)
- ชนะ: คู่แข่งล้มละลายหมด / ครบ 3 กลุ่มสี / ครบทั้งด้าน / ครบรอบที่ตั้ง (10/15/20) แล้วทรัพย์สินรวมสูงสุด
- สมบัติ 10 ชิ้น: แม่เหล็ก, แปลนก่อสร้าง, ตั๋วเที่ยวรอบโลก, โล่นางฟ้า, คูปองซื้อต่อ, กุญแจเกาะ, โบนัสเงินเดือน, ส่วนลดก่อสร้าง, ป้ายโปรโมชัน, ลูกเต๋าสำรอง (ผลและโอกาสอยู่ในแผนฉบับเต็ม)
- ลูกเต๋า: แตะหยุดหลอดเลือกช่วงแต้ม 2-4 / 5-7 / 8-10 / 11-12 · ค่าคุมแต้มของลูกเต๋า = โอกาสที่ผลจะสุ่มภายในช่วงที่เลือก · action `roll{zone}`
- `users/{uid}.marble = { dice: { owned: [], eq }, tr: { [id]: lv } }`
- RTDB: `marble/rooms/{room}/{meta,players,state,acts}` + `marble/stats/{uid}` · กฎลอกแนว `poker` ใน `database.rules.json`
- UI: CSS grid 9x9 มองจากด้านบน ไม่ใช้ canvas/game lib · ชื่อช่องดูผ่าน BottomSheet เพราะช่องกว้างราว 38px ใส่ตัวหนังสือ `.7rem` ไม่ได้
- ตัวเลขทั้งหมดรวมไว้ที่ `src/data/marble.js`

## 8. กติกา PharMarble ฉบับเต็ม (คัดจากแผน เผื่อเปิดลิงก์แผนไม่ได้)

ตัวเลขทุกตัวเป็นค่าตั้งต้นที่ยังไม่ได้ทดสอบ user สั่งไม่ต้องจูนละเอียด · sim ใช้แค่เช็กว่าเกมจบได้และไม่มีสมบัติชิ้นไหนชนะขาด

กติกาแกน
1. เริ่มคนละ 2,000K ผ่านจุดเริ่มต้นได้ 300K
2. เทิร์น: ทอย 2 ลูก → เดิน → ทำตามช่อง → จบ · แต้มคู่ได้ทอยอีก · แต้มคู่ 3 ครั้งติดไปเกาะร้าง
3. ตกช่องว่าง: ซื้อที่และสร้างได้ถึงระดับ 3 ในครั้งเดียว
4. ตกช่องตัวเอง: อัปเกรด · ระดับ 3 แล้วมาตกอีกจึงสร้างแลนด์มาร์คได้
5. ตกช่องคนอื่น: จ่ายค่าผ่านทาง แล้วเลือกซื้อต่อได้ที่ 2 เท่าของมูลค่า · แลนด์มาร์คซื้อต่อไม่ได้
6. เงินไม่พอ: ขายที่คืนธนาคารครึ่งราคา ยังไม่พอ = ล้มละลาย
7. ชนะ: คู่แข่งล้มละลายหมด / ครองครบ 3 กลุ่มสี / ครองครบทั้งด้านของกระดาน / ครบรอบ (10/15/20 ตั้งต้น 15) ทรัพย์สินรวมสูงสุด
8. หมดเวลา 25 วิต่อการตัดสินใจ = เลือกทางที่ไม่เสียเงินอัตโนมัติ · หลุดเกิน 3 เทิร์น = ออกจากเกม ที่ดินคืนธนาคาร
