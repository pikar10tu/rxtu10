# เคลียร์ข้อที่ถูกรีพอร์ทในการ์ดตรวจหลัก (Report Case Flow)

**วันที่:** 24 ก.ย. 2026 · **สถานะ:** user อนุมัติแนว B แล้ว ("เอาแบบที่เสนอเลยครับ เริ่ดมาก")
**เดโม:** https://claude.ai/artifact/Gh5MJCCDTxRsmdddJARXgc

## ปัญหา

กล่อง "🚩 ข้อที่ถูกรีพอร์ท" ใน `ReviewView.vue` มี 3 ปุ่มอิสระ: แก้ข้อนี้ / ผิดจริง (ให้รางวัล) / ไม่ผิด

1. **"ผิดจริง" จ่ายรางวัลโดยข้อไม่ถูกแก้** — `resolveReportGroup(g,'valid')` ปิดรีพอร์ท+ส่งจดหมายรางวัล แต่ข้อยังผิดและยังเผยแพร่
2. เห็นโจทย์แค่ 60 ตัวอักษร ไม่มีตัวเลือก/เฉลย — ตัดสินโดยไม่เห็นข้อ
3. ไม่มีทาง "นำออก" จากกล่องนี้
4. ปุ่มจ่ายเงินไม่มีขั้นยืนยัน
5. ตัดสิน "ไม่ผิด" ไม่นับเครดิตคนตรวจ · ผู้แจ้งไม่ได้รับแจ้งผล
6. กล่องอยู่ใต้การ์ดตรวจ+ฟอร์มยาว หาไม่เจอ
7. สองคนกดปิดรีพอร์ทชุดเดียวกันพร้อมกัน = จ่ายรางวัลซ้ำ (batch ไม่เช็คสถานะก่อนเขียน)

## โฟลวใหม่ (ผู้ตรวจเห็นอะไร)

ข้อที่ถูกรีพอร์ท **ขึ้นแทนที่การ์ดตรวจหลักก่อนคิวปกติ** ทีละข้อ (1 ข้อ = รีพอร์ททุกฉบับของข้อนั้นรวมกัน)
แบนเนอร์บนสุด: "🚩 มีข้อที่ถูกแจ้ง N ข้อ — ขึ้นให้ตรวจก่อนข้อปกติ"

การ์ดโชว์ **โจทย์เต็ม · ตัวเลือก · เฉลย · คำอธิบาย** (จาก doc สด) + รายการที่นักศึกษาแจ้ง (เหตุผล+โน้ต ทุกฉบับ)
+ ถ้าเนื้อหาข้อตอนนี้ต่างจาก snapshot ตอนแจ้ง → ป้าย "ข้อนี้ถูกแก้ไปแล้วหลังมีคนแจ้ง"

**ขั้น 1 — "ผู้แจ้งพูดถูกไหม?"**
- **ไม่ผิด ข้อสอบถูกแล้ว** → ขั้น 2a
- **ผิดจริง** → ขั้น 2b
- **ข้ามข้อนี้** → ไปข้อถัดไป (รีพอร์ทค้าง open ให้คนอื่น) · ช่อง 💬 คุยกันเรื่องข้อนี้ ใช้ได้เหมือนการ์ดปกติ

**ขั้น 2a (ไม่ผิด)** — ช่อง "บอกผู้แจ้งสั้นๆ ว่าทำไมไม่ผิด" (ไม่บังคับ) → ปุ่ม "ปิดรีพอร์ท" → ยืนยัน →
- ส่งผลตรวจ `correct` 1 เสียง (ทางเดียวกับ submit() ปกติ = ได้เครดิต, อยู่ใน `reviewedBy`)
- ปิดรีพอร์ททุกฉบับ `verdict:'invalid'` + **ส่งจดหมาย notice ถึงผู้แจ้ง** (ไม่มีรางวัล) พร้อมเหตุผลถ้ามี

**ขั้น 2b (ผิดจริง) — "จะจัดการข้อนี้ยังไง?"** (รางวัลออกตอนจัดการเสร็จเท่านั้น)
- **✏️ แก้ข้อนี้** → QuestionEditor + "แก้อะไร/ทำไม" (บังคับ) → "บันทึก + ปิดรีพอร์ท" → ยืนยัน →
  เส้นทางแก้แล้วผ่านเดิม (`reviewFixResult` + `reviews/{uid}` verdict `fixed` + เครดิต) แล้วปิดรีพอร์ท valid + รางวัล
  · ปุ่มบันทึกเปิดเมื่อชั้นตัดสิน (โจทย์/ตัวเลือก/เฉลย) เปลี่ยนเท่านั้น — "ผิดจริง" แต่ไม่แก้อะไรเลยไม่ได้
- **🗑️ นำออก** → "ทำไมถึงนำออก" (บังคับ) → "นำออก + ปิดรีพอร์ท" → ยืนยัน →
  `retired:true, isPublished:false, retiredBy:uid, retiredByName, retireReason, retiredAt` + เครดิต 1 ข้อ แล้วปิดรีพอร์ท valid + รางวัล
- **‹ ย้อนกลับ** → ขั้น 1

ทุกปุ่มที่จ่ายเหรียญ/ปิดรีพอร์ทผ่าน `useConfirm()` ที่บอกจำนวนเหรียญและจำนวนผู้แจ้ง

**ข้อที่ถูกลบ/นำออกไปแล้ว** (getDoc ไม่เจอ หรือ `retired`) → การ์ดบอกสถานะ + ปุ่มเดียว
"ปิดรีพอร์ท + ให้รางวัล" (ข้อถูกเอาออกแล้ว = รีพอร์ทมีมูล) · ไม่มีเครดิตคนตรวจ

กล่องรีพอร์ทเดิมท้ายหน้า **ลบทิ้ง** · สาขา "ปิดรีพอร์ทอัตโนมัติ" ใน `saveFix()` ของกอง failed **คงไว้**
(ข้อที่ไม่ผ่านตรวจอาจมีรีพอร์ทค้าง แก้จากกองนั้นก็ต้องปิดให้) แต่เปลี่ยนไปเรียก `resolveReports` ตัวใหม่

## ใครเห็นรีพอร์ทข้อไหน

- เฉพาะ **academic/admin** (rules `questionReports` อ่านได้แค่ `isAcademic()` — อาจารย์ไม่เห็น การ์ดรีพอร์ทไม่ขึ้นให้อาจารย์ คิวปกติเหมือนเดิม)
- `canHandleReport(q, uid)` = ไม่อยู่ใน `reviewedBy` · ไม่ใช่ `lastFixBy` · ไม่ใช่ `createdBy` (ยกเว้น `source:'import'`)
  ⇒ คนที่ตรวจ/แก้ข้อนั้นเองไม่ได้ตัดสินรีพอร์ทของข้อตัวเอง และ rules `isReviewSubmit` ผ่านเสมอสำหรับขั้น 2a
  · ถ้าไม่มีใครในทีมผ่านเงื่อนไข รีพอร์ทค้าง — แอดมินยังเห็นผ่านเครื่องมือเดิมในคลังได้ (ยอมรับได้)
- ไม่ต้องเช็คตอนโหลด (ยังไม่มีตัวข้อ) — เช็คตอนดึงตัวข้อสดมาเปิดการ์ด ถ้าไม่ผ่าน ข้ามไปกลุ่มถัดไปเงียบๆ (นับเป็น skipped ของเซสชัน)

| `composables/useReviewWrites.js` ใหม่ | เส้นเขียน Firestore ที่ใช้ร่วม: `writeFix(q, payload, reason)` (ย้ายจาก saveEdit/saveFix ที่ซ้ำกันเกือบทั้งก้อน) · `writeRetireWithCredit(q, reason)` · `resolveReports(group, verdict, note)` แบบ **transaction** อ่านสถานะก่อน — ฉบับที่ไม่ `open` แล้วข้าม ⇒ ไม่จ่ายซ้ำ |
| `components/review/ReportCaseCard.vue` ใหม่ | UI 3 ขั้นทั้งหมด · props `group`, `question` · emits `done`, `skip` · เรียก useReviewWrites + submit เสียง `correct` |
| `views/ReviewView.vue` | แบนเนอร์ + เลือกระหว่าง ReportCaseCard กับการ์ดปกติ · ลบกล่องรีพอร์ทเดิม · saveEdit/saveFix เรียก `writeFix` · แยก transaction ส่งเสียงของ submit() ออกเป็นฟังก์ชันที่ ReportCaseCard ใช้ได้ (`writeVote(q, {verdict, reason, ref, ple, note})`) |
| `firestore.rules` | ไม่ต้องแก้: `retiredBy/retireReason/...` ผ่าน `reviewUntouched()` · mail create = `isAcademic()` · reviewMeta = `canEditQuestions()` |

## จุดที่ต้องระวัง

- **ลำดับเขียนแก้ข้อ** คงเดิม: `reviews/{uid}` ก่อน `questions/{id}` (isReviewFix ใช้ existsAfter)
- ปิดรีพอร์ทหลังเขียนข้อสำเร็จเท่านั้น · ถ้าปิดรีพอร์ทพลาด ข้อแก้ไปแล้ว → toast บอกให้กดปิดซ้ำ การ์ดเปลี่ยนเป็นโหมด "ข้อจัดการแล้ว ปิดรีพอร์ทค้าง" (ปุ่มเดียว)
- `resolveReports` ใน transaction: Firestore transaction อ่านได้ ≤ 500 doc — กลุ่มหนึ่งไม่เกินหลักสิบ ปลอดภัย
- จดหมายเขียนใน transaction เดียวกับการปิดรีพอร์ท (ได้รางวัลก็ต่อเมื่อปิดสำเร็จจริง)
- ข้อความจากคนตรวจที่ส่งถึงผู้แจ้งผ่าน `cleanText(..., LIMITS.reviewReason)` · จดหมายแสดงด้วย `{{ }}` (ไม่ใช่ v-html)
- ฟอนต์ ≥ .7rem · ไม่มี overlay ใหม่ (ฟอร์มอยู่ในการ์ด) จึงไม่ต้อง Teleport

## ไม่ทำในรอบนี้ (YAGNI)

- ไม่แก้ช่องโหว่ "แก้แล้วผ่านทับ reviewedBy คนตรวจเดิม" (แยกเรื่อง)
- ไม่แก้ rule ที่ผู้แจ้ง re-report แล้วเปิดรีพอร์ทที่ปิดไปแล้วได้
- ไม่ทำเกณฑ์ลำดับรีพอร์ท (เรียงตามใหม่สุดก่อนเหมือน `groupReports` เดิม)
