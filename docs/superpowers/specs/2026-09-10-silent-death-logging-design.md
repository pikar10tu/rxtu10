## 3. แนวทางที่เลือก — "ยิง attack event เงียบ"

`resolveSilentDeath()` push event หน้าตาเดียวกับหมัดปกติ:

```js
{ t: 'attack', side: killer.side, attacker: killer.uid, target: unit.uid,
  dmg: 0, sub: true, dead: true, silent: true,
  crit: false, eff: 'neutral', dodged: false, targetHpAfter: 0 }
```

**เหตุผลที่เลือกแนวนี้แทนการเพิ่ม event ชนิดใหม่ (`t:'death'`) หรือธง `alsoDead[]` บน event เดิม:**

โจทย์นี้ไม่ใช่ "เพิ่มข้อมูลใหม่เข้า log" แต่คือ **"การตายที่ควรอยู่ใน log ตั้งแต่แรกแต่หล่นหาย"**
ใช้รูปแบบเดิมจึงไม่ใช่การโกหก และได้ผู้อ่านทั้งหมดมาฟรีโดยไม่ต้องแก้ทีละที่ —
ซึ่งสำคัญมากเพราะ **"ผู้อ่าน log ที่ลืมอัปเดต = พังเงียบ"** เป็นตระกูลบั๊กที่กัดโปรเจกต์นี้มาหลายรอบ
(ป้าย `grit` หาย · `kind` ชนกับ `fxKind` · เพ็ทสอง part โดนลดเป็น `skillQuiet`)

ธง `silent: true` มีไว้บอกตรงๆ ว่าใบนี้มาจากทางไหน — ไม่ใช่หมัดที่ผู้ตีเหวี่ยงออกไปเอง

**ภาพที่ออกมาเล่าตรงตามกติกาที่ผู้ใช้เคาะไว้ใน §7.6 เป๊ะ** — 🦔 เม่นออกหมัดใส่ 🐕 แล้ว 🐕 ดับ
ก็คือ "เจ้าของหนามเป็นผู้ฆ่า" จริงๆ ไม่ต้องตีความเพิ่ม

## 4. เอนจิน — ยิง event ตรงไหน

`resolveSilentDeath()` เป็นจุดเดียวที่ตัดสินว่า "ตายจริงไหม" อยู่แล้ว ⇒ ให้เป็นจุดเดียวที่ยิง event ด้วย

```
resolveSilentDeath(unit, killer, { announced })
   ├ hp > 0        → ไม่ใช่การตาย จบ (พร้อมเคลียร์ _deathDone ตามเดิม)
   ├ _deathDone    → เส้นทางอื่นรันไปแล้ว จบ
   ├ runOnDeath()  → ฟีนิกซ์คืนชีพ / แมว cheatDeath / grit …
   │     └ prevented → ไม่ตาย ⇒ ไม่มี event การตาย (จบตรงนี้)
   ├ 💀 push ใบการตายเงียบ  ← เฉพาะเมื่อ announced === false
   └ runOnAnyDeath()  → ทีเร็กซ์ได้ชั้น
```

### 4.1 พารามิเตอร์ `announced` — ตัวกันใบซ้ำ

| ใครเรียก | `announced` | เหตุผล |
|---|---|---|
| `strike()` เป้าหลัก (`tg`) | **true** | ใบ `attack` จริงของหมัดนั้นแบก `dead` อยู่แล้ว ยิงอีกใบ = นับตายสองครั้ง |
| หนาม (`att` หลัง `strike()` จบ) | false | ไม่มีใบไหนพูดถึงการตายนี้เลย |
| `guardian` (`hitRes.guard`) | false | เหมือนกัน |
| `aoeOpener` ก่อนรอบ 1 | false | event เป็นชนิด `passive` ไม่มีช่อง `dead` |

🔴 **ค่าเริ่มต้นต้องเป็น `announced: false`** — จุดเรียกที่ลืมส่งจะได้ "ใบเกิน" ซึ่งเทสจับได้ทันที
(`death-audit` และเทสนับใบ) ต่างจากค่าเริ่มต้น `true` ที่ลืมแล้ว "ใบหาย" = กลับไปเป็นบั๊กเดิมแบบเงียบ

### 4.2 ลำดับที่ตั้งใจ

- ใบการตายอยู่ **หลัง** `runOnDeath` — เพราะถ้ากันตายได้ (revive/cheatDeath/grit) ต้องไม่มีใบเลย
- ใบการตายอยู่ **ก่อน** `runOnAnyDeath` — เหตุมาก่อนผล (ตายแล้วทีเร็กซ์ถึงได้ชั้น)
- ทั้งสามทางถูกเรียก**หลัง**ใบ `attack` ของหมัดแม่ถูก push แล้ว (กติกาเดิมใน `battleEngine.js`
  ที่ย้ำว่า "เหตุต้องมาก่อนผลเสมอ") ⇒ ใบการตายตกอยู่ในบีตเดียวกับหมัดที่ทำให้ตาย = ไม่เพิ่มเวลา

⚠️ **ไม่แตะลำดับ event ของหมัดปกติ** — `runOnDeath`/`runOnAnyDeath` ยัง log ก่อนใบ `attack` ของหมัดแม่
เหมือนเดิม ซึ่ง `battleBeats` รับมือได้อยู่แล้ว

### 4.3 🔴 ค่าที่คืนต้องเปลี่ยนความหมายเป็น "ใบนี้เป็นคนประกาศการตายหรือเปล่า"

**นี่คือรูรั่วที่ต้องอุดพร้อมกัน ไม่ใช่ของแถม** — ถ้าลืม จะได้ "นับตายสองครั้ง" แทนที่จะเป็น "ตายหาย"

วันนี้ `resolveSilentDeath()` คืน `true` ตอนเจอธง `_deathDone` (แปลว่า "ตายไปแล้วจากเส้นทางอื่น")
และ `strike()` เอาค่านั้นไปใส่ `dead` ของใบ `attack` ตรงๆ — **ถูกต้องตอนที่ยังไม่มีใบการตายเงียบ**
เพราะใบนั้นเป็นบันทึกเดียวที่มีอยู่ แต่พอเราเพิ่มใบการตายเงียบเข้าไป เส้นทางซ้อนจะได้สองใบ:

```
X ตี Y (Y มีเกราะสะท้อน)
  └ Y ยิงก้อนสะท้อนใส่ v ผ่าน strike() ชั้นใน
      └ Y โดนหนามของ v สวนตายกลางชั้นใน
          └ resolveSilentDeath(Y, killer=v, announced:false)
              → 💀 ใบการตายเงียบ  (ผู้ฆ่า = v)          ← ใบที่ 1
  └ กลับมาที่ strike() ชั้นนอก: resolveSilentDeath(Y, killer=X, announced:true)
      → _deathDone แล้ว → คืน true → ใบ attack ของ X ได้ dead:true   ← ใบที่ 2 (ผู้ฆ่า = X)
```

⇒ `battleSummary` แจกเครดิต `kills` ให้ **ทั้ง v และ X** จากศพใบเดียว

**แก้:** กิ่ง `_deathDone` **คืน `false`** และนิยามค่าที่คืนใหม่เป็น
**"การตายครั้งนี้ถูกประกาศโดยการเรียกครั้งนี้หรือเปล่า"** (ไม่ใช่ "ตายหรือเปล่า")

ผลที่ตามมาและถือว่าถูกต้องตามกติกา §7.6 ที่ผู้ใช้เคาะไว้ (**"ใครสร้างดาเมจ คนนั้นคือผู้ฆ่า"**):

- ใบ `attack` ของ X ได้ `dead: false` — X ไม่ได้ฆ่า Y จริง หนามของ v ต่างหากที่ฆ่า
- `hit()` จึงไม่ตั้ง `killed` ให้ X ⇒ **X ไม่ได้ `killChain`** จากศพที่ตัวเองไม่ได้ฆ่า
- เคสปกติ (ไม่ซ้อน) ค่าไม่เปลี่ยน: ประกาศเอง = คืน `true` เหมือนเดิมทุกประการ

🔒 ต้องมีเทสที่ยิงไฟต์จริงแล้วยืนยันว่า **ศพหนึ่งใบมีบันทึกการตายหนึ่งใบเสมอ** (นับ `dead === true`
ต่อ uid ต้องไม่เกิน 1 ต่อการตายหนึ่งครั้ง) — เป็นค่าคงที่ระดับเดียวกับที่ `_deathDone` กันฮุคซ้ำ

### 5.1 สิ่งที่เห็นบนจอ

ภายในบีตเดิมทั้งหมด: 🦔 เม่นสวนหนาม → 💥 ประกายน็อกที่การ์ด 🐕 → หลอดเลือดลงถึง 0
(ทุกวันนี้หลอดไม่ขยับเลย) → การ์ดจางเป็นสีเทา

## 6. 🦖 ทีเร็กซ์เริ่มที่ 1 ชั้น

ของเดิม: `{ hook:'onAnyDeath', effect:'stackAtk', value:{ pct:12, max:3 }, step:{ pct:4, max:0 } }`

**ทำ:** เติม `start: 1` ลงใน `value` (พร้อม `start: 0` ใน `step` เพราะไม่สเกลตามเกรด ตามกติกา P1
ที่ทุกคีย์ใน value ต้องมีคีย์คู่ใน step) แล้วให้ hook `setup` เป็นคนเติมชั้นแรก

🔴 **ห้ามเพิ่ม part ที่สอง** — เพ็ทที่ถือ `stackAtk` สอง part คือกับดักของหนี้ข้อ 2 พอดี (§7)
`runSetup()` ต้องมองหา part ที่มี `value.start > 0` จาก part เดิมตัวนั้นเอง ไม่ใช่ part ใหม่

**ผลของเลข:** ชั้นคูณทบกัน (`atk *= 1 + pct/100` ต่อชั้น) ไม่ใช่บวก ⇒ ตัน 3 ชั้น = 1.12³ = **+40.5%**
ของใหม่ทำให้ถึง +40.5% ได้เร็วขึ้น 1 ตัว **ไม่ได้แรงกว่าเพดานเดิม**

⚠️ **ต้องแก้ `desc`/`short` ด้วย** — ข้อความปัจจุบันบอกว่า "ศัตรูล้ม 1 ตัว พลังโจมตี +{pct}%"
ซึ่งจะไม่ตรงอีกต่อไป · ต้องบอกเลขตรงๆ ไม่ใช้คำไม่ทางการ ตามกติกา §11 ของสเปกแม่
(มีเทสบังคับกติกานี้อยู่แล้ว 3 เคส — เขียนผิดกฎเทสแดงทันที)

📌 **บันทึกไว้ให้ P4:** งานตายเงียบใน §4 **บัฟทีเร็กซ์ให้อยู่แล้วโดยไม่ต้องแตะเลข** — การตายที่ log
ไม่เคยบันทึกคือชั้นที่มันควรได้แต่ไม่เคยได้ (เคสหนักสุดที่ §7.6 วัดไว้: ทีม `[บาฮามุท g5, ทีเร็กซ์ g3]`
เจอ common g0 ⇒ ทีเร็กซ์ได้ **0 ชั้นใน 50/50 ไฟต์**) ⇒ **ชั้นแถมนี้ซ้อนอยู่บนบัฟนั้นอีกที**
P4 ต้องวัดผลรวมของสองอย่างพร้อมกัน ไม่ใช่คิดว่าชั้นแถมคือความเปลี่ยนแปลงเดียว

## 7. หนี้ §7.6 อีก 4 ข้อ

### ข้อ 3 — โมเมนต์ `grit` ของแมว
เติม `'grit'` เข้า `CLUTCH_EFFECTS` (`battleBeats.js:42`) — บรรทัดเดียว + เทส

วันนี้การกันตายชั้นที่ 2–3 ของแมวได้ `skillQuiet` 0ms ทั้งที่กฎข้างๆ เขียนไว้เองว่า
"จังหวะเป็น-ตาย ได้โมเมนต์เต็มเสมอ แม้เป็นครั้งซ้ำ" และพี่ของมัน (`cheatDeath`) อยู่ในเซ็ตแล้ว

**ไม่ต้องมีป้าย** — `grit` เป็น runtime state ที่ไม่มีวันเป็น `part.effect` และ event ของมันใช้ไอคอนแมวเอง
ผ่าน `p.icon` อยู่แล้ว (แพทเทิร์นเดียวกับ `infectBurst`) · การตัดสินใจของ P2c-1 ที่ไม่ลงทะเบียนป้ายถูกแล้ว
ไม่ต้องรื้อ — badge ถาวรที่อ่าน runtime จริง (ถ้าจะทำ) ต้องผ่าน `liveBuffs()` ซึ่งเป็นหนี้ข้อ 7 คนละก้อน

### ข้อ 5 — `killChain` เล่นต่อจากบีตปิดเกม
pass ที่ให้ `kind` กับ event ชนิด `passive` วิ่งจาก `openCut` ถึงท้าย log โดยไม่รู้จัก `finishAt`
⇒ event หลังใบปิดเกม (เช่น `killChain`/`stackAtk` จาก `runOnKill` ของการฆ่าที่ปิดไฟต์) ได้ `skill` 200ms
= เล่นต่อทั้งที่ไฟต์จบแล้ว

**กฎใหม่:** passive ที่อยู่หลังใบปิดเกม = `skillQuiet` (0ms) — ไฟต์จบแล้วไม่มีอะไรเล่นต่อ

### ข้อ 2 — เพดาน `atkStacks` ไม่ตรงกัน 3 แหล่ง
`onRound` max 4 (อูโรโบรอส) · `onAnyDeath` max 3 (ทีเร็กซ์) · `onKill` max 3 — ใช้ `st.atkStacks` ร่วมกัน
วันที่เพ็ทตัวเดียวถือสองแหล่ง เพดานต่ำจะบล็อกอีกแหล่งเงียบๆ โดยไม่มี event บอก

**ตัดสินใจ: ไม่แยก state ตอนนี้** — วันนี้ไม่มีเพ็ทตัวไหนถือสองแหล่ง การรื้อ `atkStacks` กระทบ
`buffSources`/`liveBuffs`/ช่อง `amount` ในทุก event โดยยังไม่มีใครได้ประโยชน์ (YAGNI)

**แทนที่ด้วยเทสที่แดงทันทีวันที่มีเพ็ทถือ `stackAtk` ≥ 2 part** พร้อมข้อความบอกวิธีแยก state
⇒ เปลี่ยน "พังเงียบตอน P3" เป็น "พังดังตอนเขียนโค้ด"

🔑 การเติม `start` ของทีเร็กซ์ (§6) **ไม่ทำให้มันกลายเป็นสองแหล่ง** — ยัง part เดียว เทสต้องยังเขียว

### ข้อ 8 — ช่องว่างเทสที่รู้ตัว
- เทสเพดาน `stackAtk` ของอูโรโบรอส (max 4) — วันนี้ไม่มีเลย
- ย้ายสคริปต์ inline ที่ตรวจจังหวะเพ็ทสอง part มาเป็นเทสถาวรใน `battleBeats.test.js`
- สาขา reflect ของธง `countering` **ยังพิสูจน์กับไฟต์จริงไม่ได้** จนกว่าจะมีเพ็ทถือ `armorStack`
  (งาน P3) — บันทึกไว้ ไม่ฝืนทำ

ตามที่ §7.6 เตือนไว้ล่วงหน้าแล้ว

3. `npm run build` ผ่าน
4. **วัด sim baseline ใหม่** เก็บลง `docs/` — baseline ของ P2c-1
   (`docs/pet-passive-sim-p2c1-2026-09-05.md`) ใช้ไม่ได้อีก และ P4 ต้องใช้ต่อ

   จะได้รู้ขนาดของผลกระทบตอนอธิบายให้ผู้เล่นฟัง

## 9. ไม่ทำในเฟสนี้ (ตั้งใจตัด)

- **หนี้ข้อ 7 (ฝั่งแสดงผล)** — `buffSources()` เป็น static ก่อนไฟต์ อ่าน runtime state ไม่ได้
  ⇒ ป้าย `elementTrinity` โกหกได้ · `liveBuffs` ไม่โชว์ชั้นของ `atkOnHit` · `grit` ไม่มี badge
  เป็นงานฝั่ง UI ทั้งก้อน ต้องรื้อ `liveBuffs()` — คนละเรื่องกับเอนจิน แยกเป็นเฟสของตัวเอง
- **หนี้ข้อ 4** ("ทนอีก 2 หมัด" ≠ "ทนอีก 2 จังหวะ" เมื่อเจอเซอร์เบอรัสที่สุ่มเป้าซ้ำได้)
  — ไม่ใช่บั๊ก เป็นเรื่องเลขของ P4 · บันทึกไว้เฉยๆ
- **แยก state ของ `atkStacks`** — ดู §7 ข้อ 2
- **นับดาเมจพาสสีฟเข้าหน้าสรุป** — ผู้ใช้เคาะว่าไม่เอา เลขดาเมจคงเดิม
