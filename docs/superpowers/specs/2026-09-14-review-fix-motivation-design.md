# ตรวจข้อสอบ: แก้แล้ว = ผ่านเลย ไม่ต้องวนหาคนใหม่ตรวจ (2026-09-14)

## โจทย์

เพื่อนวิชาการแจ้งว่าระบบตรวจ**ไม่จูงใจ**: ถ้าเจอข้อที่ต้องแก้ แล้วลงมือแก้เนื้อหาเอง —
1. ตัวเอง**ไม่ถูกนับว่าได้ตรวจข้อนี้** (ไม่ขึ้น leaderboard)
2. ข้อยัง**วนกลับเข้าคิว `pending` ให้คนใหม่ตรวจซ้ำ** ทั้งที่แก้ถูกแล้ว

คนที่ทำงานหนักสุด (อ่าน+ตัดสิน+แก้) กลับได้แต้ม 0 ในขณะที่กด "ถูกต้อง" เฉยๆ ได้แต้มปกติ

user เห็นด้วยกับข้อเสนอของเพื่อน: **ตัด verdict "ผิด"/"ต้องแก้" (ที่แค่ตีธงไม่แก้เนื้อหา) ออก
ใครเจอผิดให้แก้เลยในตาเดียว แก้แล้วนับว่าผ่านการตรวจทันที คนแก้ได้แต้ม
+ เพิ่มแต้มย้อนหลังให้คนที่แก้ไปแล้วรอบนี้แต่ยังไม่ได้เครดิต**

## สิ่งที่พบตอนสำรวจ (`ReviewView.vue` + `questionReview.js` + `firestore.rules`)

ระบบมี **2 เส้นทางเขียนที่แยกกันสนิท** และนี่คือต้นเหตุของบั๊กเชิงพฤติกรรมนี้:

1. **`submit()`** — กด verdict (✅ถูกต้อง / 🛠️ต้องแก้ / ❌ผิด) + ส่งผล → เขียนผ่าน transaction
   นับ `reviewedBy`/`reviewPass`/`reviewFail` และ **บวก `reviewMeta.counts[uid]` (leaderboard) เสมอไม่ว่า verdict ไหน**
   — เส้นทางนี้ไม่มีบั๊ก คนตีว่า "ผิด" เฉยๆ ได้เครดิตอยู่แล้ว

2. **`saveEdit()` (requeue branch) / `saveFix()`** — กด "✏️ แก้ข้อนี้" แล้วแก้โจทย์/ตัวเลือก/เฉลยจริง
   → เขียนผ่าน `updateDoc` ธรรมดา ด้วย `REVIEW_RESET` (`reviewedBy:[], reviewPass:0, reviewFail:0,
   reviewStatus:'pending'`) + `lastFixBy` แล้ว `pickNext()` — **ไม่แตะ `reviewMeta.counts` เลย**
   คนแก้จริงไม่ได้เครดิตอะไร แล้วข้อกลับไป `pending` ให้คนอื่นตรวจใหม่ทั้งชุด

`needsReviewBy()` กันคนที่ `lastFixBy === myUid` ไม่ให้ตรวจข้อที่ตัวเองแก้ (กันตรวจงานตัวเอง)
ซึ่งถูกแล้วในระบบเดิม — แต่ผลคือ**คนแก้ไม่มีทางได้เครดิตจากข้อนั้นอีกเลยตลอดกาล**

## ขอบเขต

**แตะ**: verdict ที่เลือกได้ในหน้าตรวจ, เส้นทางเขียนของการ "แก้ข้อ" (ทั้งจากการ์ดปัจจุบัน และกอง
"🗂️ ไม่ผ่านตรวจ"), `firestore.rules` (เพิ่มฟังก์ชันใหม่), แถบ "แก้ผลตรวจที่เพิ่งส่ง" (ตัดออก),
เครดิตย้อนหลัง (migration ครั้งเดียว)

**ไม่แตะ**: เกณฑ์ 1 คน/ข้อ, โครง `conflict` ของเก่า (รอคนที่ 3), โครงคิว 2 ก้อน (ต้นทุน read คงที่),
กอง "ไม่มีกลุ่มโรค" (`nogroup`), ระบบคอมเมนต์ท้ายข้อ, ปุ่ม "นำออก"

## ดีไซน์

### 1. Verdict เหลือ 2 ทางเท่านั้น

- **✅ ถูกต้อง** — เหมือนเดิมทุกอย่าง ผ่าน `submit()`
- **🛠️ แก้แล้ว** — เดิมคือ "แก้ข้อนี้" ที่แก้ชั้นตัดสิน (โจทย์/ตัวเลือก/เฉลย) แล้วกด "บันทึกการแก้"
  กลายเป็น**การตรวจที่จบในตาเดียว** ไม่ใช่แค่แก้เนื้อหาเฉยๆ อีกต่อไป

ตัดปุ่ม "🛠️ ต้องแก้" / "❌ ผิด" ออกจาก `VERDICTS` ในฟอร์มตรวจหลักไปเลย — **ไม่มีทาง "ตีว่าผิดโดยไม่แก้"
อีกแล้ว** เจอปัญหาที่ไม่มั่นใจจะแก้เอง (เช่นต้องปรึกษาผู้เชี่ยวชาญยา) ให้ใช้ "ข้ามข้อนี้" (มีอยู่แล้ว)
+ ทิ้งโน้ตไว้ในคอมเมนต์ท้ายข้อ (มีอยู่แล้ว) แทน

### 2. เส้นทางเขียนใหม่: "แก้แล้วผ่าน" (ใช้ทั้งการ์ดปัจจุบัน + กอง "ไม่ผ่านตรวจ")

เพิ่มช่อง **"แก้อะไร/ทำไม" (บังคับพิมพ์)** ในฟอร์มแก้ — บังคับเฉพาะตอนแก้ชั้นตัดสิน (เดิมคือ
`editRequeues`/ทุกกรณีของ `saveFix`) ไม่บังคับตอนแก้แค่ชั้นประกอบ (คำอธิบาย/หมายเหตุ — พฤติกรรมเดิม
ไม่เปลี่ยน ไม่นับเป็นตรวจ)

กด "บันทึกการแก้" (ชั้นตัดสินเปลี่ยน) → เขียนครั้งเดียว:
```
{ ...payload,                                    // เนื้อหาใหม่
  reviewedBy: [uid], reviewPass: 1, reviewFail: 0, reviewStatus: 'passed',
  lastFixBy: uid, lastFixByName, lastFixAt: serverTimestamp(),
  updatedAt: serverTimestamp() }
+ reviews/{uid}: { verdict: 'fixed', reason, ref, ts }   // verdict ใหม่ แยกจาก 'correct'
+ reviewMeta.counts[uid] += 1  (leaderboard)
+ reviewMeta.progress: ขยับ oldStatus → 'passed' (guard from!==to เหมือน bumpedProgress())
```
ไม่ต้องใช้ transaction — ตั้งค่าตายตัวทั้งชุด ไม่ต้องอ่านค่าเดิมมาคำนวณ (ต่างจาก `submit()` ที่ increment)

**ไม่กลับเข้าคิว `pending` อีกแล้ว** — toast เปลี่ยนเป็น "แก้และตรวจผ่านแล้ว ขอบคุณ!"

`VERDICT_LABEL` เพิ่ม `fixed: 'แก้แล้วผ่าน'` (สีเขียวเหมือน correct แต่ป้ายบอกว่าผ่านเพราะแก้)
ใช้กับกล่อง "แก้โดย...แก้อะไร" (`priorFixedReviews`) ที่มีอยู่แล้ว — ยังทำงานเหมือนเดิม
(ข้อที่ถูกแก้แล้วผ่านซ้ำอีกรอบในอนาคต จะเห็นเหตุผลของรอบก่อนได้ตามปกติ)

### 3. `firestore.rules` — เพิ่มฟังก์ชันใหม่ `isReviewFix()`

`isReviewReset()` ปัจจุบันอนุญาตเขียนเนื้อหา+ล้างผลตรวจกลับ `pending` พร้อมกัน (ไม่มี `hasOnly`)
แต่ไม่มีทางเขียนเนื้อหา+ตั้งผลเป็น `passed` พร้อมกันในตาเดียว ต้องเพิ่ม:

```
function isReviewFix(qid) {
  return request.resource.data.get('reviewedBy', []) == [request.auth.uid]
    && request.resource.data.get('reviewPass', 0) == 1
    && request.resource.data.get('reviewFail', 0) == 0
    && request.resource.data.get('reviewStatus', '') == 'passed'
    && request.resource.data.get('lastFixBy', '') == request.auth.uid
    && existsAfter(/databases/$(database)/documents/questions/$(qid)/reviews/$(request.auth.uid));
}
```
เพิ่มเข้า `allow update` คู่กับ `isReviewReset()` — **ต้อง `firebase deploy --only firestore:rules`
ก่อน push โค้ด** (ลำดับเดียวกับ CLAUDE.md ข้อ 14 — client เก่าที่ยังไม่มี rules ใหม่จะเขียนไม่ผ่าน
permission ถ้าสลับลำดับ)

### 4. เครดิตย้อนหลัง — ปุ่มแอดมิน one-time (idempotent)

⚠️ **`syncReviewSystem()` (ปุ่ม "🔄 ซิงก์ระบบตรวจ" ที่มีอยู่แล้ว) เขียน `reviewMeta.counts`/`progress`
ทับทั้งก้อนใหม่ทุกครั้งที่กด โดยคำนวณจาก `reviewedBy` ของทุกข้อล้วนๆ** (`tallyReviewCounts`) —
ถ้าเครดิตย้อนหลังถูกเก็บไว้แค่ในตัวนับแยก (เช่น increment ตรงๆ) จะถูกปุ่มนี้ล้างทิ้งเงียบๆ ในการกดครั้งถัดไป
**ทางที่ทนกว่าคือเติมคนแก้เข้า `reviewedBy` จริงถาวร** ให้กลไกเดิมที่ sync เชื่อถืออยู่แล้วเห็นและนับให้เอง
ตลอดไป ไม่ต้องมีฟิลด์ marker แยก (`fixCredited`) เพราะการเช็ค "ยังไม่อยู่ใน `reviewedBy`" ทำให้กดซ้ำ
ปลอดภัยอยู่แล้วโดยตัวมันเอง:

ฟิลด์ `lastFixBy` เพิ่งเกิดตอน deploy ลูปตรวจ 11 ก.ย. 2026 (`ac6aeeb`) — ของก่อนหน้าไม่มีอยู่แล้ว
โดยธรรมชาติ จึงสแกน `questions` ที่มี `lastFixBy` และ **`lastFixBy` ยังไม่อยู่ใน `reviewedBy`**:

- เติม `lastFixBy` เข้า `reviewedBy` (array เดิม + ชื่อนี้) เสมอ — ให้ `tallyReviewCounts()` นับเขาได้
  ตลอดไปไม่ว่าจะกดซิงก์อีกกี่ครั้ง
- ถ้าสถานะที่คำนวณได้ตอนนี้ (ก่อนแก้ `reviewedBy`) เป็น `pending` (ยังไม่มีใครตรวจซ้ำตั้งแต่แก้)
  → ตั้ง `reviewPass:1, reviewFail:0, reviewStatus:'passed'` ไปด้วยในตาเดียว — ปิดลูปให้เลย
- ถ้ามีคนตรวจซ้ำไปแล้ว (สถานะเป็น passed/failed/conflict) → เติมแค่ `reviewedBy` ไม่แตะ
  `reviewPass`/`reviewFail`/`reviewStatus` ที่คนอื่นตัดสินไปแล้ว (เครดิตความพยายาม ไม่เปลี่ยนผลตัดสิน)
- จบแล้ว **รันซ้ำแพทเทิร์นเดียวกับท้าย `syncReviewSystem()`**: recompute `reviewMeta.progress` จาก
  `reviewStatusKey()` ของทุกข้อ (หลังแพตช์) + `reviewMeta.counts` จาก `tallyReviewCounts(all)`
  (หลังแพตช์) ในทรานแซกชันเดียว — และต้อง**เติม `names[lastFixBy] = q.lastFixByName` เข้าไปด้วย**
  (คนที่เคยแก้แต่ไม่เคยกด "ถูกต้อง" ผ่าน `submit()` เลย จะไม่มีชื่ออยู่ใน `reviewMeta.names` มาก่อน
  ⇒ ไม่เติมจะโชว์เป็น "ไม่ระบุ" ใน leaderboard ทั้งที่มีตัวเลข)

วางในหน้า Admin เป็นปุ่มใหม่ (แพทเทิร์นเดียวกับ "🔄 ซิงก์ระบบตรวจ")

### 5. ตัดฟีเจอร์ "แก้ผลตรวจที่เพิ่งส่ง" (`lastSubmit`/`amending`/`submitAmend`)

เดิมมีไว้สลับ verdict ที่ตัวเองเพิ่งส่ง (correct↔fix↔wrong) พอเหลือ verdict เดียวที่กดผ่าน `submit()`
("ถูกต้อง") ไม่มีอะไรให้สลับไปแล้ว — **user เคาะให้ตัดทั้งแถบ `rv-last` และฟังก์ชัน `submitAmend()`ออก**
(ถ้าจะแก้เนื้อหาจริงๆ ใช้ปุ่ม "แก้ข้อนี้" ซึ่งเป็นคนละเส้นทางเขียนอยู่แล้ว)

## การตัดสินใจของ user (เคาะแล้ว — อย่าเปิดใหม่)

- ✅ ช่อง "แก้อะไร/ทำไม" **บังคับพิมพ์** ตอนแก้ชั้นตัดสิน
- ✅ เครดิตย้อนหลังนับทุกข้อที่มี `lastFixBy` อยู่ (เท่ากับตั้งแต่ deploy 11 ก.ย. โดยธรรมชาติของฟิลด์)
- ✅ ตัดแถบ "แก้ผลตรวจที่เพิ่งส่ง" ทิ้งทั้งชุด ไม่เก็บไว้เผื่ออนาคต
- ❌ ไม่มี "ตีว่าผิดเฉยๆ ไม่แก้" อีกแล้ว — เจอปัญหาที่แก้เองไม่ได้ ใช้ข้าม+คอมเมนต์แทน
