## 2. กันเพ็ทใหม่ไม่ให้หลุดก่อน P5

### ปัญหา
`PETS` (`src/data/index.js`) เป็น **คลังกลางของทุกอย่าง** — กาชา · เป้าการันตี · ตู้หลอม · ทีมบอทหอคอย ·
ตัวหาร "x/27 ชนิด" · achievement เก็บครบ ⇒ แค่เพิ่ม 6 ตัวเข้าไปเฉยๆ เพ็ทที่ยังไม่เปิดตัวจะหลุดออกทุกทาง
และเปอร์เซ็นต์สะสมของทุกคนจะตกฟรีโดยไม่มีใครทำอะไรผิด

### รูปที่เลือก
- `PETS` เต็ม **33 ตัว** · เพ็ทใหม่ 6 ตัวติดฟิลด์ **`wave: 2`**
  🔑 ตั้งชื่อว่า `wave` ไม่ใช่ `unreleased` เพราะฟิลด์นี้ **อยู่ถาวร ไม่ถูกลบตอน P5** — มันคือ "รุ่นที่เข้าเกม"
  ไม่ใช่ "ยังไม่เปิด" · ของที่ต้องนิ่งตลอดกาล (หอคอย) จะอ้างรุ่น ส่วนของที่เปิดตามอีเวนต์จะอ้าง config
- ฟังก์ชันบริสุทธิ์ตัวเดียวเป็นด่าน: **`releasedPets(gachaEvent, now)`** ใน `src/utils/petCatalog.js`

| สภาวะ | คืนอะไร |
|---|---|
| ไม่มี `config/app.gachaEvent` (สภาพวันนี้) | 27 ตัว (wave 1) — **ดีฟอลต์ปลอดภัย** |
| มีอีเวนต์ · `now <= endsAt` | 27 ตัว (ตู้ปกติ) — ตู้พิเศษของ P5 จะเรียกคลังเต็มเอง |
| มีอีเวนต์ · `now > endsAt` | 33 ตัว **อัตโนมัติ ไม่ต้องกดปุ่มแอดมิน** (กติกาข้อ 7 ของสเปกแม่) |

⚠️ แปลว่า **การเปิดตัว 6 ตัวนี้เกิดขึ้นได้ทางเดียวคือมี `gachaEvent` จริงใน Firestore** — เป็นงานของ P5
ไม่ใช่ของ P3 · P3 แค่วางด่านและพิสูจน์ด้วยเทสว่าด่านปิดสนิท

## 5. เปลี่ยนเอนจิน 1 จุด — `giantSlayer` เป็นธรณีประตูเดียว

**เดิม (P2a):** ไต่ขั้นละ 10% ที่ `maxHp` เป้าสูงกว่าเรา × `v.pct` แล้วชนเพดาน `v.max`
**ใหม่ (user เคาะ 10 ก.ย.):** `target.maxHp > att.maxHp` → ดาเมจ **+`v.pct`% คงที่** · ไม่มีเพดาน · ไม่มีการไต่ขั้น

```js
case 'giantSlayer': {
  if (!target) break
  if (target.maxHp <= att.maxHp) break
  res.atkMult *= 1 + v.pct / 100
  res.events.push(ev(att, p, part, { targets: [att.uid], amount: Math.round(v.pct), fxKind: 'buff' }))
  break
}
```

ที่ต้องตามไปแก้ในคอมมิตเดียวกัน:
- **ลบคีย์ `max` ออกจากสัญญาของ `giantSlayer`** — ค่าคงที่ที่ไม่มีใครอ่านอันตรายกว่าค่าที่ผิด
- เทสของ P2a ที่ล็อกพฤติกรรมไต่ขั้น/ชนเพดาน → เขียนใหม่ให้ล็อกธรณีประตูแทน
- `STATUS_TEXT.giantSlayer` 'ยิ่งเป้าตัวใหญ่ยิ่งแรง' → **'ตีเป้าตัวใหญ่กว่าแรงขึ้น'**
- ดอคบล็อกของ `ev()` เขียนไว้ว่า "giantSlayer ห้ามส่งเป็นจำนวนขั้นเพราะมีเพดาน" — เหตุผลเปลี่ยนแล้ว
  (ตอนนี้ `amount` = % คงที่) ต้องแก้คอมเมนต์ให้ตรง ไม่ปล่อยให้เป็นเหตุผลที่ตายไปแล้ว
- `stepsOf10()` ยังมี 🐗 `berserk` ใช้อยู่ ⇒ **ห้ามลบ**

2. 🔴 **🐹 แฮมสเตอร์ 200%** ทำให้หมัดเปิดของ common แรงกว่าหมัดเปิดของ 🐉 ในหลายคู่ — ตั้งใจตามที่ user เคาะ
   แต่ sim ต้องตรวจว่ามันไม่ได้ทำให้ "เปิดเกมแล้วจบเกม"
3. 🔴 **ห้ามเชื่อ lift ของ 🐘 บากุ / 🧞 จินนี่ จาก `passive-power-sim`** (สนามวัดไม่มีหนาม/guardian) — หนี้เดิมจาก P2c-2
4. ⏸ **หนี้ §7.6 ข้อ 4 ยังเปิด** — "แมวทนอีก 2 หมัด" ≠ "2 จังหวะ" · P3 ไม่ได้เพิ่มเพ็ท multi-hit ตัวใหม่
   (👾 ไม่ใช่ multi-hit) ⇒ สถานะเท่าเดิม ยังเป็นเรื่องเลขของ P4
5. **baseline ของ P4 คือ `docs/pet-passive-sim-p2c2-2026-09-10.md`** — ต้องวัดใหม่หลัง P3a เพราะ 5 ตัวเปลี่ยนกลไก

### ความเสี่ยงของ P3 เอง
6. **`elementTrinity` คูณ `maxHp` แล้วเซ็ต `hp = maxHp`** — อยู่ใน `applyAuras` ซึ่งรันตอนเริ่มไฟต์ จึงปลอดภัย
   🔴 แต่ห้ามมีใครไปเรียกซ้ำกลางไฟต์เด็ดขาด (`maxHp` plain ห้ามเป็น ref — บทเรียนเดิมของโปรเจกต์)
7. **`stealStats` ต้องรันก่อน `applyAuras`** — เอนจินทำถูกอยู่แล้ว (`runSetup`) แต่ 🦁 ที่คูณ `maxHp` ตอน aura
   ทำให้ลำดับนี้สำคัญกว่าเดิม: หนูขโมยจากเลขก่อนสิงโตบัฟ **มีเทสล็อกลำดับ**
8. **🦇 `teamLifesteal` + 🦄 `healOnAttack` ในทีมเดียวกัน** — สเปก P2 §7.4 ข้อ 7 เตือนว่าถ้ายิงบน uid เดียวกัน
   ติดกัน กฎจังหวะจะปิดเสียงใบแรก · วันนี้เป็นคนละเพ็ท (uid ต่างกัน) จึงยังไม่ชน **แต่ต้องมีเทสยืนยัน**
   ไม่ใช่เดาจากการอ่านโค้ด
